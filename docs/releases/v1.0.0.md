# LangGraph Coding Agent v1.0.0

状态：Stable。Day15 代码、离线验证、UI 复核与发布材料已收口。

## 结构化需求契约

- Coordinator 在不增加 Agent 或模型调用的情况下生成版本化 `requirement_contract`。
- 契约记录规范化目标、显式 `.cs` 文件、单文件边界、工程保护约束，以及审批、Code Checker、Unity 编译、Unity Test、Reviewer 和 Git 提交门禁。
- 空需求以 `EMPTY_QUERY` 安全停止，不进入 Architecture 等下游节点。
- Architecture、File Planner 与 Reviewer 使用同一份检查点契约；旧检查点和直接调用仍保留基于原始需求的单文件范围兜底。

## 发布工程

- `project_version.py` 是 v1.0.0 的单一版本来源，并用于 Gradio 页面标题。
- `python -m tools.environment_check` 只读检查 Python、Provider 路由覆盖、Unity、生成代码独立仓库和 Git 身份；不调用网络、不修改文件、不输出密钥。
- `.github/workflows/offline-ci.yml` 在 Python 3.11 执行完整离线测试、`compileall` 和 `git diff --check`，不依赖 Provider、Unity 或仓库密钥。
- `generated/` 明确作为运行时生成代码的独立 Git 仓库，由主仓库整目录忽略；已有内容不会在发布过程中删除。
- Day15 Notebook 可在无 LLM、无 Unity、无网络环境下复核需求契约、固定评估指标和发布产物一致性。

## UI 收口

- 现有审批 UI 修改纳入 v1.0.0：执行时间文案明确为“任务总历时（含人工等待）”。
- 批准全部、批准所选和拒绝操作隐藏 Gradio 默认进度覆盖层，保留工作流自身的实时进度展示。
- Gradio 页面标题读取统一版本来源。

## 安全边界

- Coder 与 Repair 仍只生成待人工审批的补丁；批准前不写生产代码。
- 只有 Code Checker、Unity 编译、EditMode 测试和 Reviewer 全部通过后，才允许本地 Git 提交。
- Agent 不提供任意 Shell、push、PR、merge、rebase、reset 或历史改写入口。
- 环境预检和离线 Notebook 不打印 API Key、Authorization、完整 Prompt、模型响应或生成代码正文。
- 标签、远程推送和 GitHub Release 需要维护者单独授权。

## 兼容性

- Python 3.10+；离线 CI 使用 Python 3.11。
- Gradio 6.22.x，LangGraph SQLite 检查点保持现有协议。
- Unity 验收环境继续使用 Unity 2022.3 LTS 与 EditMode Test Framework。
- 新任务自动获得需求契约；旧检查点缺少该字段时仍可通过原始 `query` 和既有范围逻辑恢复。
- `GENERATED_SOURCE_PATH` 应指向具有基线提交与 Git 身份的独立仓库；未配置时保留当前项目内 `generated/` 默认路径。

## 已知限制

- 当前真实执行面向本地 Unity C# 项目，自动测试以 EditMode 为主；PlayMode 和团队级远程执行仍属后续范围。
- GitHub Actions 仅覆盖离线 Python 验证，不能替代真实 Provider + Unity 验收。
- Gradio 测试在 Windows 下仍会输出非失败的未关闭事件循环 `ResourceWarning`。
- Windows 下 `nbconvert` 的 ZeroMQ 内核关闭过程可能输出 Proactor 兼容性警告；本次执行进程返回 0，五个代码单元均有执行计数且错误输出为 0。
- `generated/` 中恢复的真实 Unity 任务仍停在 Repair 人工审批点；其运行时代码和审批结果不属于主仓库 v1.0 发布内容。
