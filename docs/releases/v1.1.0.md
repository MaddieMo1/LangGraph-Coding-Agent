# LangGraph Coding Agent v1.1.0

状态：Stable。v1.1.0 收录 v1.0.0 之后已经合并并验收的 Day16～Day18 能力，保持现有需求契约、人工审批、Unity 质量门和本地 Git 所有权边界。

## Unity API 可信知识检索

- 在 Project Understanding 与 Architecture 之间加入确定性的 Unity Knowledge 节点，不增加 LLM Agent。
- 默认离线并优先使用项目知识与版本化缓存；受控联网仅允许 Unity 官方文档域名。
- 对 HTTPS、重定向、内容长度、Unity 版本和提示词注入进行校验，最多向下游提供 3 条有界只读证据。
- Architecture、Coder、Reviewer 与 Repair 可以引用可信 API 证据，但证据不能扩大结构化需求契约或批准文件范围。

## 审批审计与本地权限控制

- 服务启动时绑定 `viewer`、`reviewer`、`approver` 或 `operator` 本地角色，服务端统一执行能力检查。
- 审批、验证、Repair 和本地 Git 关键事件写入按项目隔离、哈希链接的 JSONL 审计链。
- 审批状态与审计记录采用事务式边界和失败补偿；重复请求保持幂等，敏感备注经过清理。
- 当前身份是可信本机启动身份，不是浏览器登录、账号系统或远程角色切换。

## 团队只读观察

- 同一 FastAPI/Gradio 服务提供 `/observe` 只读 JSON/SSE 接口和 `/observe/ui` 浏览器页面，不引入第二套工作流进程。
- checkpoint 继续作为权威状态；独立 SQLite 表只保存经过字段白名单和脱敏的派生快照与事件。
- SSE 使用单调游标、`Last-Event-ID` 和 `after_cursor` 支持断线续传、游标重置和多观察者在线状态。
- 观察任务显示有界、脱敏的可读名称；完整 Prompt、源码、Diff、绝对路径、环境变量和凭据不进入远程响应。
- 本机控制台增加“团队观察”入口；局域网来源只能进入观察面，控制面根路径、API 文档和控制 WebSocket 均被拒绝。

## 安全边界

- Coder 与 Repair 仍只生成待审批补丁，批准前不写入生产代码。
- 只有 Code Checker、Unity 编译、EditMode 测试和 Reviewer 全部通过后，才允许在任务分支创建本地提交。
- 团队观察共享令牌只用于换取 `HttpOnly`、`SameSite=Strict` 会话 Cookie，不进入 URL、持久化浏览器存储或应用日志。
- 远程观察路由没有批准、拒绝、继续、重试、取消、归档、Git 或文件写入能力。
- 发布产物不包含 `.env`、API Key、观察令牌、运行数据库、日志、生成代码仓库或完整模型输入输出。

## 兼容性

- Python 3.10+；离线 CI 使用 Python 3.11。
- Gradio 6.22.x；Unity 验收环境使用 Unity 2022.3 LTS 与 EditMode Test Framework。
- 现有 LangGraph SQLite checkpoint 协议保持不变；Day18 只增加独立派生表，旧 checkpoint 可在启动时只读重建观察投影。
- 旧任务缺少结构化需求目标时，可读任务名称安全回退到经过脱敏和长度限制的原始查询。
- 团队观察默认关闭；现有本机部署不配置观察环境变量时继续只监听回环地址。

## 已知限制

- 共享观察令牌适合可信小型局域网，不等同于账号、SSO、每人独立授权或完整远程身份审计。
- 未配置 TLS 时，局域网 HTTP 可能被同网段窃听；生产部署应配置 TLS 或受控反向代理。
- SQLite checkpoint、审计和观察派生存储面向单机服务与小规模观察者，不支持多节点水平扩展。
- 自动 Unity 验收仍以 EditMode 为主；PlayMode 和团队级远程执行属于后续范围。
- GitHub Actions 的离线门禁不能替代真实 Provider、Unity、反向代理或证书链验收。
