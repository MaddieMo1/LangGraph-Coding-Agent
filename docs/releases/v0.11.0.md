## 工作流恢复与 UI

- 失败任务可沿用原 thread、任务分支和批准文件重新生成测试或重新进入 Repair，无需刷新后从头生成生产代码。
- 工作台显示开始时间和实时执行耗时；任务中心支持状态统计、搜索、筛选、分页、详情抽屉和非活动任务批量删除。
- 首次审批和 Repair 复审均保留可滚动 Diff；Repair 原因卡展示失败门禁、错误代码、根因、涉及文件和修复策略。
- README 更新六张真实 UI 截图，覆盖任务入口、首次审批、Repair 复审、任务中心、详情证据和最终完成状态。

## Day13 多模型路由（自 v0.9.0 后新增）

- Architecture、File Planner、Coder、Test Generator、Reviewer 和 Repair 按角色与确定性复杂度路由 DeepSeek、Kimi、Qwen 与 GLM。
- 结构化输出失败时先在当前模型进行一次格式纠正；仍失败或 Provider 调用失败时，最多跨 Provider 回退一次。
- 路由、复杂度、选择原因、请求次数、耗时、Token usage 和回退状态持久化并在 UI 只读展示。

## 安全边界

- Coder 与 Repair 仅生成待人工审批的补丁；批准前不修改生产文件。
- 只有 Code Checker、Unity 编译、EditMode 测试和 Reviewer 全部通过后，才在独立生成代码仓库创建本地提交。
- Agent 不执行 push、PR、merge、rebase、reset 或历史改写；本次 GitHub 发布由维护者在主项目仓库显式执行。
- API Key、Authorization、完整 Prompt、完整模型响应和生成代码正文不进入评估 fixture、报告或 README。
