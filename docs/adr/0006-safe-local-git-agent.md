# ADR 0006：安全的本地 Git Agent

- 状态：Accepted
- 日期：2026-08-11

## 背景

Day11 已确保 Coder 与 Repair 的生产代码变更必须先由人工批准，但批准后的文件仍缺少可审计的本地版本边界。直接让模型执行任意 Git 或 Shell 命令会扩大权限，也可能把用户原有改动、未批准文件或敏感配置混入提交。

## 决策

Day12 引入确定性的 `GitTool` 与薄编排层 `GitAgent`。`GitTool` 只暴露仓库检查、身份检查、Diff、创建 `agent/<id>` 分支、按路径暂存、读取暂存文件和本地提交；调用参数始终是固定参数数组，不接受任意 Git 子命令或 Shell 字符串。

正常工作流先执行 `git_prepare`：生成代码目录必须是已初始化、已有基线提交且工作区干净的独立 Git 仓库。准备成功后创建任务分支。Day11 每次批准都会把接受文件的路径、操作和目标哈希写入持久化状态；后续修复批准会覆盖同一路径的旧证据。

只有 Code Checker、Unity Compiler、Unity Test 与 Reviewer 全部通过时，工作流才进入 `git_commit`。提交前逐个验证当前内容仍等于最新批准哈希，仅暂存批准路径，并检查暂存区没有额外文件。提交信息由确定性生成器输出中文 Conventional Commit 标题。

## 结果

- 用户必须先为生成代码建立清晰、干净的 Git 基线。
- AI 无法使用 `git add .`，也无法提交未批准路径。
- 批准后的外部文件漂移会阻止提交。
- 测试、编译或审核失败不会创建提交。
- 分支、基准提交、最终 commit hash、提交信息和错误会进入 LangGraph 持久化状态及本地 UI。

## 非目标

- `git push`、远程分支、Pull Request 或 GitHub API。
- `reset`、`stash`、`merge`、`rebase`、强制切换或历史改写。
- 自动处理用户已有的脏工作区。
- 允许模型生成并执行任意命令。
## 运行准备

`GENERATED_SOURCE_PATH` 指向生成代码仓库根目录，默认为项目内 `generated/`。该目录需要先执行一次 `git init`，配置 Git 身份并创建基线提交。任务开始后若出现未提交改动、仓库没有 `HEAD` 或当前路径只是其他仓库的子目录，工作流会以结构化 Git 错误安全结束。
