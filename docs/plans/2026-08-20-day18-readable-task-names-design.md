# Day18 可读任务名称设计

## 目标

在局域网只读观察页中，将 `状态 · 门禁 · 短任务编号` 改为 `状态 · 中文任务名称 · 短任务编号`，同时保持完整 Prompt、源码、Diff、密钥和绝对路径不出现在远程契约中。

## 已确认方案

采用方案 A：从 checkpoint 中已有的 `requirement_contract.goal` 提取任务名称；旧 checkpoint 缺少契约时回退到 `query`。名称经过现有文本清理规则处理，移除控制字符，遮蔽 Authorization、密钥和绝对路径，压缩空白并截断为 32 个字符。空名称显示“未命名任务”。

`task_name` 作为只读快照的新增白名单字段写入派生观察表。事件仍只传递状态变化，避免重复携带任务文本；观察页从任务列表和快照读取名称。服务启动时的只读 reconciliation 会为现有 checkpoint 补齐名称，不执行或推进工作流。

## UI

下拉项格式为：`completed · 创建背包物品管理系统 · f1434a45`。页面仍显示短任务编号以便排查和对应日志。名称只用于展示，不参与任务选择、路由、审批或所有权判断。

## 配置说明

真正生效的上级 `.env` 保留全部现有值，只在模型、检索、Unity/生成仓库、观察服务和本地身份配置组上增加中文注释。

## 验收

- 中文任务名称能从需求目标生成并限制在 32 字符内。
- 路径、Authorization 和 secret-like 内容不会出现在名称中。
- 旧 checkpoint 返回“未命名任务”。
- 下拉框同时显示状态、名称和 8 位任务编号。
- Day18 专项、完整回归、Python 编译和空白检查通过。
